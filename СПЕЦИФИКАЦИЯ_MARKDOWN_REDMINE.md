# Спецификация Markdown для Redmine

Документ описывает правила написания Markdown, который конвертируется
в Textile для публикации в Redmine wiki.

Конвертация выполняется командой:

```bash
make
```

или вручную:

```bash
pandoc --lua-filter=redmine_textile.lua -f markdown -t textile file.md -o file.redmine.textile
```

---

## Поддерживаемые конструкции

### Заголовки

```markdown
## Заголовок 2
### Заголовок 3
```

Результат: `h2. Заголовок 2`, `h3. Заголовок 3`

Ограничение: только уровни h1-h4.

### Параграфы

Обычный текст. Параграфы разделяются пустой строкой.

Строки внутри одного параграфа можно переносить —
они объединятся в один абзац.

### Код-блоки (fenced)

```markdown
​```bash
echo hello
​```
```

Результат: `<pre><code class="bash">...</code></pre>`

Поддерживаемые языки: `bash`, `shell`, `text`, `xml` и любые другие.
Если язык не указан, используется `text`.

Знак `$` внутри код-блоков обрабатывается корректно —
он автоматически экранируется в HTML-сущность `&#36;`.

### Inline-код

```markdown
Используйте `kinit` для получения билета.
```

Результат: `Используйте @kinit@ для получения билета.`

### Маркированные списки

```markdown
- первый элемент
- второй элемент
  с продолжением на новой строке
- третий элемент
```

Результат: `* первый элемент`, `* второй элемент с продолжением...`

Многострочные элементы объединяются в одну строку.

### Нумерованные списки

```markdown
1. первый шаг
2. второй шаг
```

Результат: `# первый шаг`, `# второй шаг`

### Жирный текст и курсив

```markdown
**жирный текст** в параграфе.
*курсив* и ***жирный курсив***.
```

Результат: `*жирный текст*`, `_курсив_`, `*_жирный курсив_*`

### Ссылки

```markdown
- [Текст ссылки](http://example.com/path)
```

Результат: `* "Текст ссылки":http://example.com/path`

## Ограничения

### Bold внутри элементов списка

Bold (`**...**`) внутри элементов списка ломает Textile-разметку,
так как `*` конфликтует с маркером списка.

Запрещено:

```markdown
- **SPN**: уникальный идентификатор
```

Разрешено:

```markdown
- SPN: уникальный идентификатор
```

Если нужно выделить заголовок списка — ставьте его перед списком:

```markdown
**Ключевые понятия**:

- DNS и Kerberos: строго привязан к именам
- SPN: уникальный идентификатор
```

### Blockquote (`> ...`)

Конвертируется в `bq. ...` (стандартный синтаксис Textile).
Поддерживается в Redmine (Textile 2+), но если ваша версия Redmine
не рендерит `bq.`, используйте обычный текст с форматированием.

### HTML-комментарии

HTML-комментарии (`<!-- ... -->`) автоматически вырезаются
при конвертации и не попадают в Textile-вывод.

Это можно использовать для заметок, которые нужны только в Markdown:

```markdown
<!-- TODO: проверить в Redmine 4.0 -->
```

#### Textile оглавление

Для оглавления просто вставляем HTML коментарий как показано ниже:

```markdown
<!-- toc -->
```

В результате будет сгенерирован следующий код:

```textile
{{>toc}}
```

### Код-блок без пустой строки перед заголовком

Не требуется. Фильтр автоматически добавляет пустую строку
после закрывающего `</code></pre>`.

Оба варианта работают корректно:

```markdown
​```bash
code
​```
## заголовок
```

```markdown
​```bash
code
​```

## заголовок
```

### Вложенные списки

Вложенные списки (с отступом) преобразуются в плоские.
Если нужна иерархия — используйте нумерацию или текстовое оформление.

## Структура проекта

```
.
├── redmine_textile.lua      # Lua-фильтр конвертации
├── Makefile                  # make = конвертация всех .md файлов
├── test_runner.sh            # тесты конвертации (TDD)
├── tests/                    # входные MD-файлы для тестов
├── expected/                 # эталонные Textile-результаты
├── actual/                   # фактические результаты (gitignored)
└── *.md                      # статьи
```

### Запуск тестов

```
bash test_runner.sh                # все тесты
bash test_runner.sh 20 21          # конкретные тесты по номеру
bash test_runner.sh --verbose      # с diff при ошибках
bash test_runner.sh --update       # обновить эталоны
```

---

## Чеклист перед коммитом

1. `bash test_runner.sh` — все тесты проходят
2. Нет bold (`**...**`) внутри элементов списка
3. Нет blockquote (`> ...`), если Redmine не поддерживает `bq.`
4. Код-блоки используют fenced-синтаксис (` ``` `), не отступы
5. `make` отрабатывает без ошибок
